**gameStore.js changes:**

Add two new fields to the story section (alongside hasSeenStoryIntro):
```javascript
hasCompletedOnboarding: false,
onboardingStep: 0,  // 0=not started, 1=first word seen, 2=first correct, 3=completed
setHasCompletedOnboarding: (value) => a[0]({ hasCompletedOnboarding: value }),
setOnboardingStep: (step) => a[0]({ onboardingStep: step }),
```

Add these two fields to the `partialize` function so they persist:
```javascript
hasCompletedOnboarding: state.hasCompletedOnboarding,
onboardingStep: state.onboardingStep,
```

In the `onRehydrateStorage` callback, after migration, add backward compat:
```javascript
// Backward compat: existing users with hasSeenStoryIntro=true skip onboarding
if (state.hasSeenStoryIntro && !state.hasCompletedOnboarding) {
  useGameStore.setState({ hasCompletedOnboarding: true, onboardingStep: 3 });
}
```

**WordAdventure.jsx changes:**

1. Add `hasCompletedOnboarding` and `setHasCompletedOnboarding` to the gameStore destructuring.
2. Remove the StoryIntro overlay rendering at the bottom of the JSX. Delete or comment out the line:
   ```
   {!hasSeenStoryIntro && userProfile && <StoryIntro gender={userProfile.gender} onComplete={() => setHasSeenStoryIntro(true)} />}
   ```
3. Replace with new onboarding logic: after profile creation (WelcomeScreen completes), if `!hasCompletedOnboarding`, auto-start level 1 by calling `logic.startLevel(1)` in a useEffect that fires when `userProfile` is set and `!hasCompletedOnboarding`:
   ```javascript
   useEffect(() => {
       if (userProfile && !hasCompletedOnboarding && gameState === 'start') {
           // Auto-start level 1 for new players
           logic.startLevel(1);
           // Also mark story intro as seen so StoryPathChoice doesn't block
           if (!hasSeenStoryIntro) {
               setHasSeenStoryIntro(true);
           }
       }
   }, [userProfile, hasCompletedOnboarding]);
   ```
4. Remove the StoryPathChoice overlay for new users during onboarding. Change the StoryPathChoice condition from:
   ```
   {!story.progress.storyPath && hasSeenStoryIntro && userProfile && <StoryPathChoice ... />}
   ```
   to:
   ```
   {!story.progress.storyPath && hasCompletedOnboarding && userProfile && <StoryPathChoice ... />}
   ```
   This defers story path choice to AFTER completing the first level (matches research recommendation).

5. Pass `onboardingStep` and related data through screenProps if needed (or let useGameLogic read it directly from store).

**useGameLogic.js changes:**

Add onboarding hint support in processAnswer:
1. Import `useGameStore` if not already imported, read `onboardingStep` and `setOnboardingStep` and `setHasCompletedOnboarding`.
2. In processAnswer, after processing a correct answer, check onboarding state:
   - If `onboardingStep === 0`: set to 1 (first word attempted)
   - If `onboardingStep === 1` and answer is correct: set to 2 (first correct answer)
   - If `onboardingStep === 2`: set to 3 and set `hasCompletedOnboarding` to true
3. This allows the onboarding to complete after the player gets a few answers right in level 1, feeling natural rather than forced.

Actually, simplify: track onboarding by level completion. In the level complete handler (when a level is completed in processAnswer or wherever levelComplete is triggered), check: if `!hasCompletedOnboarding` and we just completed level 1 (or any level), set `hasCompletedOnboarding: true` and `onboardingStep: 3`. This is simpler and more reliable -- the first lesson IS the onboarding.

**Do NOT:**
- Delete StoryIntro.jsx file (it still exists for potential reuse)
- Break existing users: anyone with `hasSeenStoryIntro: true` must get `hasCompletedOnboarding: true` via the rehydration hook
- Remove StoryPathChoice entirely -- just defer it to after onboarding
