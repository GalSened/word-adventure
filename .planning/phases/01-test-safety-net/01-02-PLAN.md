**Step 1: Set up global mocks at the top of the file (before imports)**

Mock `framer-motion` globally using a Proxy pattern. This replaces every `motion.X` element with a plain HTML element, stripping framer-motion-specific props (animate, initial, exit, variants, transition, whileHover, whileTap, whileFocus, whileInView, layout, layoutId). Replace `AnimatePresence` with a component that renders children directly. Also mock `useAnimation`, `useMotionValue`, `useTransform`.

```javascript
vi.mock('framer-motion', () => {
  const React = require('react')
  const motion = new Proxy({}, {
    get: (_, tag) => {
      return React.forwardRef(({ children, ...props }, ref) => {
        const {
          animate, initial, exit, variants, transition,
          whileHover, whileTap, whileFocus, whileInView,
          layout, layoutId, onAnimationComplete, drag, dragConstraints,
          ...htmlProps
        } = props
        return React.createElement(tag, { ...htmlProps, ref }, children)
      })
    }
  })
  return {
    __esModule: true,
    motion,
    AnimatePresence: ({ children }) => children,
    useAnimation: () => ({ start: vi.fn(), stop: vi.fn() }),
    useMotionValue: (val) => ({ get: () => val, set: vi.fn() }),
    useTransform: (val) => val,
  }
})
```

**Step 3: Write the 6 snapshot tests**

**Test 1 — "welcome" state (no userProfile):**
Do NOT set any userProfile in localStorage. Render `<WordAdventure />`. The component checks `if (!userProfile)` and returns `<WelcomeScreen />`. Snapshot the container.

**Test 2 — "start" state:**
Set localStorage with a valid userProfile: `localStorage.setItem('userProfile', JSON.stringify({ name: 'Test', gender: 'boy', avatar: '🧙' }))`. Render `<WordAdventure />`. The component initializes with `gameState='start'` and renders the main menu. Snapshot the container.

**Test 3 — "map" state:**
Same localStorage setup as start. Render `<WordAdventure />`. Use `fireEvent.click` to click the "מפת עולמות" (world map) button. The button has text content "מפת עולמות" — find it with `screen.getByText('מפת עולמות')` and click it. This sets gameState to 'map'. Snapshot after click.

**Test 4 — "playing" state:**
Same localStorage setup. Render the component. Navigate to map first (click "מפת עולמות"). Then find and click a level button to start playing. The map renders level buttons — the first unlocked level is 'easy'. Find the button by looking for text or role. The level buttons contain the chapter title text, e.g., "הממלכה הקסומה". Click it to enter playing state. Snapshot after click.

IMPORTANT: The `startLevel` function sets `activeWords` and `gameState='playing'`. For this to work, the words data must be available. The `initialWordData` is hardcoded in the component, so it should work. However, if clicking the level button goes through story intro logic, you may need to also handle `showStoryIntro`. If the story intro shows, either:
- Pre-set `localStorage.setItem('hasSeenStoryIntro', JSON.stringify(true))` before rendering, OR
- Click through the story intro overlay

Use the simpler approach: set `hasSeenStoryIntro` to true in localStorage before rendering for the playing, levelComplete, and gameOver tests.

**Test 5 — "levelComplete" state:**
This is the hardest state to reach organically. The most pragmatic approach: render and navigate to playing state (as in Test 4), then simulate answering all words correctly to trigger levelComplete.

However, this is complex. A simpler alternative: After reaching playing state, mock the component's internal state. But since we cannot set useState from outside, the practical approach is:
- Navigate to playing state as in Test 4
- Find the input/letter picker and simulate answering the current word correctly
- Repeat for all active words (there are 5 easy words in initialWordData)
- Each correct answer calls `processAnswer(true)`, and when `currentWordIndex >= activeWords.length - 1`, it sets gameState to 'levelComplete'

For each word in the easy level (CAT, DOG, SUN, BOOK, FISH):
- The playing state renders a LetterPicker component. Find the letter buttons and click them in order to spell the word, then find and click the check/submit button.
- OR: If the LetterPicker has an input, use `fireEvent.change` to set the value and `fireEvent.submit` on the form.
- The exact interaction depends on LetterPicker's implementation. Read LetterPicker to determine the correct interaction pattern.

If this proves too complex during execution (>15 minutes of debugging), fall back to: snapshot the playing state container and add a comment noting that levelComplete/gameOver require deeper component interaction. The executor should attempt the full approach first.

**Test 6 — "gameOver" state:**
Navigate to playing state. Simulate 3 incorrect answers (wrong words) to deplete lives. When lives reach 0, `processAnswer(false)` sets gameState to 'gameOver'.

Similar interaction pattern to Test 5 but with wrong answers. Submit an incorrect word 3 times.

- If any snapshot contains non-deterministic content (IDs with timestamps), mock `Date.now` and `Math.random` for that test

**If snapshots are very large (>200 lines):** That is fine for characterization tests. They capture the full DOM tree. Do not try to reduce them — their purpose is regression detection.
