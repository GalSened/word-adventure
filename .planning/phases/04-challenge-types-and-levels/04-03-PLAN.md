**1. Update useGameLogic.js:**

Import `selectChallengeType` from `../utils/challengeSelector`.

Add state tracking for current challenge type:
- Add `challengeType` to the state read from useGameStore. Since challengeType is ephemeral (not persisted), add it via the game slice as a new field with `setChallengeType` setter.
- OR (simpler, avoids store changes): Track `challengeType` as a local variable computed when `currentWord` changes. Use `useMemo` keyed on `[currentWordIndex, activeWords]`:

```javascript
const challengeType = useMemo(() => {
    if (!currentWord) return 'spelling';
    // Grammar-generated words always get grammar challenge
    if (currentWord.id?.startsWith('gen_')) return 'grammar';
    // Select based on SRS mastery
    const srsState = useGameStore.getState().userProgress[currentWord.id];
    return selectChallengeType(currentWord, srsState, recentChallengeTypes);
}, [currentWordIndex, activeWords]);
```

Track `recentChallengeTypes` as a ref (useRef) -- an array of last 3 challenge types used. Push the new type on each word change. This prevents repetitive challenge sequences.

Add an `onAnswer` callback that delegates directly to `processAnswer`:
```javascript
const onAnswer = (isCorrect) => {
    processAnswer(isCorrect);
};
```

**Why this works without refactoring:** `processAnswer` in useGameLogic.js already accepts `isCorrect` as its sole parameter (see line ~107: `const processAnswer = (isCorrect) => { ... }`). It does NOT read `userInput` or check correctness internally -- that input-checking logic lives in `handleCheck`, which calls `processAnswer(true)` or `processAnswer(false)` after comparing input. So `onAnswer` is a trivial passthrough: non-spelling challenge components call `onAnswer(true/false)` which calls `processAnswer(true/false)` directly, bypassing `handleCheck`'s input comparison. For spelling challenges, the existing `handleCheck` -> `processAnswer` flow remains unchanged.

Return `challengeType` and `onAnswer` from the hook alongside existing returns.
